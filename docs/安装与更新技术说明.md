# KnowledgeTree 0.1.1 安装、配置与更新

## 本次范围

0.1.0 是升级基线，0.1.1 新增正式启动与本地配置机制。当前是个人离线开发版本，没有公网发布源。官方 Updater 已集成，但未配置 HTTPS 地址和公钥时不联网，不允许安装未验证更新。Windows Authenticode 与 Updater 签名属于不同机制，当前本地安装包没有 Authenticode 证书。

## 审计依据

原 `src-tauri/src/lib.rs` 在 setup 中选择环境变量或固定 `<legacy-library>`，立即调用会创建目录的 `Library::open`。React 直接列举学科，无目录引导。主题、布局、相机、面板和草稿使用 localStorage，键没有知识库隔离。Schema 已有 `format_version: 1`，但缺失字段无法读取。Mutex 只保护本进程。Updater 未配置。原 NSIS 安装包早于最终 UX EXE，尽管均为 0.1.0。

## 模块与配置

- `config.rs`：标准配置目录中的 `config.json`；配置版本、知识库路径、偏好、旧偏好导入标记、检查频率。配置写入同步磁盘并保留 `config.previous`；原配置缺失时读取 previous，损坏或未来配置拒绝覆盖。
- `lifecycle.rs`：启动状态、创建、打开、切换、原生文件夹选择和完整备份。
- `library_session.rs`：结构校验、目录保护、跨进程锁、旧程序检测、SHA256 验证备份。
- `updates.rs`：官方 Updater 的检查、下载、签名验证与安装封装。前端不直接获得任意文件权限。
- `frontend/src/lifecycle/`：欢迎界面、设置与更新界面、偏好缓存、生命周期保存屏障。

应用标识始终为 `dev.knowledgetree.desktop`，产品名为 `Knowledge Tree`。正常运行的配置目录由 Tauri `app_config_dir()` 获取；Windows 通常是 `%APPDATA%\dev.knowledgetree.desktop`。窗口状态插件保存同目录 `.window-state.json`。

配置 preferences 保存主题、布局，以及按知识库规范化路径隔离的学科选择、面板、相机和未保存草稿。草稿成功保存后清除对应值。旧 localStorage 在自动接入旧固定路径或环境变量明确指定的库时导入一次，不删除原缓存。属性恢复发现可能冲突时要求选择恢复草稿或保留磁盘内容。

`KNOWLEDGE_TREE_LIBRARY` 非空时仅覆盖本次运行，不覆盖保存的知识库路径；无效覆盖明确报错，不回退到另一知识库。环境覆盖模式禁止切换目录。

开发验证可用 `KNOWLEDGE_TREE_CONFIG_DIR` 指定隔离配置目录。该模式关闭系统窗口状态插件，旧库探测仅检查配置目录同级的 `legacy`，避免碰真实固定路径。桌面自动化同时指定 `WEBVIEW2_USER_DATA_FOLDER`，隔离 WebView 缓存。生产运行不要设置这些测试变量。

## 四种操作

1. 首次初始化：仅创建新目录或空目录；二次检查空目录，禁止静默覆盖。写入根标记 `.knowledge-tree.json`，Schema 1。学科仍按用户创建，不注入示例知识。
2. 普通启动：有效配置直接连接；没有配置时识别旧固定路径并原地保存路径；不移动、重建或重新初始化旧库。
3. 切换：保存正文、属性、结构任务与配置，验证新库后才更换会话；失败保留旧会话。退出旧工作区后重置会话撤销记录，偏好和草稿按库隔离。
4. 格式迁移：0.1.1 不改变 Schema 1，没有必须执行的结构迁移。缺失版本字段按既有结构严格校验后读取为 Schema 1，读取不改文件；正常编辑可能补写版本字段。未知版本拒绝连接、拒绝写入，不删除重建。未来结构迁移必须在完整备份副本中执行并添加可恢复提交日志；不能复用初始化作为迁移。

已有库必须选择包含学科文件夹的根目录。扫描验证 YAML、正文可读性、ID、父链、阶段与关系端点；任一学科异常不会被静默忽略。暂不支持符号链接、Windows 联接点或外置 Git worktree。任意非库目录不能当作库打开。旧库不会添加根标记或改写 YAML，但会使用锁文件及临时权限探针。

## 数据保护

应用配置有独占进程锁；知识库有持有文件句柄的独占锁，进程退出由 OS 释放，锁文件无需手工删除。每次写入与备份检查其他已知 KnowledgeTree 进程，阻止检测到的 0.1.0 同时运行。

0.1.0 本身不遵守新锁。重命名旧程序、检测后的启动竞态或外部编辑工具不能由普通文件锁绝对排除。因此升级操作必须关闭旧程序；不宣称对任意非协作进程实现完全互斥。已有单文件替换也不是跨文件事务，不宣称普通保存具备完整事务能力。

完整备份默认放在配置目录 `backups/schema1-时间戳`，包含整个知识库（Markdown、YAML、附件、隐藏文件、完整 `.git` 与空目录）、设置快照和窗口状态。知识库锁不复制。遍历拒绝链接；源文件复制前后与副本逐文件 SHA256 对照；变化或复制失败不标记为可用备份。备份目标不能存在，不能放在源库内部。失败不删除原库，残留不完整副本保留供检查。外部工具同时写入时仍应停用外部编辑，尤其迁移时。

已有 YAML 保存保留未知扩展键，不会把未来扩展元数据全部丢弃；已知可选属性被用户清空时正常移除。Git 提交失败仍保留知识文件，Git 不是完整升级备份。

## 更新流程

启动后延迟检查，不阻塞知识库使用。成功检查间隔 24 小时；失败从 30 分钟退避，最多 24 小时。手动检查跳过时间限制。没有发布源时不请求网络，设置页明确显示状态。

下载在 Rust 中使用官方 `Update::download`，返回包前验证签名；版本也必须与签名 trusted comment 绑定，禁止 downgrade。更新清单与下载 URL 都要求 HTTPS，保持系统证书验证。下载失败可重试，不安装。当前构建使用 Windows 系统 TLS。

安装前前端停止后台工作区交互，等待保存队列、结构任务及配置持久化；保存失败阻止安装。然后创建并验证完整备份，用户确认后调用安装。后端冻结写入并保存配置及窗口状态。Windows 官方插件启动安装器后退出，安装器负责重启；新版按原配置恢复。安装器启动失败解除冻结。安装器已启动后的 OS/安装错误需要重新运行已保留安装包恢复程序，用户知识数据始终位于安装目录之外，不承诺自动回滚整个 Windows 安装。

官方说明：https://v2.tauri.app/plugin/updater/

## 构建与发布

| 类型 | 命令/产物 |
| --- | --- |
| Development | `pnpm dev`，Vite + Tauri，不是可分发程序 |
| Release | `pnpm --dir apps/desktop build --no-bundle`，独立 EXE 与需要的 WebView2Loader DLL |
| Installer | `scripts/release-windows.ps1`，NSIS 当前用户安装版 |
| Update Package | `scripts/release-windows.ps1 -PublishUpdate -ArtifactBaseUrl HTTPS下载目录`，NSIS 安装包及 `.sig` |

当前机器无 MSVC linker，使用已安装 GNU 工具链；正式 Windows 发布仍优先考虑 MSVC。NSIS 安装模式固定 currentUser，不能随意切换到 perMachine。安装目录由安装器保持，不包含知识库。软件标识、产品名和配置目录必须稳定。构建不意味着安装验收通过。

发布更新需设置 `KNOWLEDGE_TREE_UPDATE_URL`、`KNOWLEDGE_TREE_UPDATE_PUBLIC_KEY` 及 `TAURI_SIGNING_PRIVATE_KEY`（推荐私钥文件路径）。私钥不放仓库，设置访问控制并离线备份；不能用每次生成的新密钥给已有用户发布。`tauri signer generate` 建立正式密钥；手动签包用 `--app-version` 绑定版本。发布脚本没有自动上传步骤。

发布源清单至少包含 version、notes、platforms.windows-x86_64.url 和 platforms.windows-x86_64.signature（`.sig` 内容）。安装器与签名文件属于同一次构建；构建复制产物到 `dist/releases/版本` 并记录 SHA256，禁止覆盖既有发布目录。

## 验证与发布门槛

每次发布应在隔离 Windows 用户/虚拟机完成新装、0.1.0 覆盖安装、应用内签名更新、离线启动、保存失败、下载失败、未知格式拒绝及设置恢复。数据核对包含 YAML、Markdown、附件、Git 历史及应用设置，不能只比较节点数。当前具体执行结果见 `0.1.1验证记录.md`；未执行项不能作为通过。

知识库路径禁止位于应用安装、配置和缓存目录之内，也不能包含这些目录；避免卸载程序的应用数据清理涉及知识记录。安装器禁止版本降级。
