# 插画知识树

本文记录 0.1.0 的插画布局验收；当前 0.1.1 启动与更新机制见 [技术说明](安装与更新技术说明.md)。

## 模块

| 模块 | 职责 |
| --- | --- |
| `botanical-skeleton.ts` | 一根渐细主干、5 根错位主枝、每枝 4 个二级枝槽位、每个槽位 3 个枝梢槽位，以及少量装饰叶片。 |
| `illustrated-tree-layout.ts` | 读取现有 `TreeLayout` 和 `Stage`，忽略旧坐标；按父子关系、阶段和节点类型映射知识；维护所有原始 ID 到骨架位置及详情集合的索引。 |
| `illustrated-tree-projection.ts` | 按缩放决定语义层次，筛选屏幕内内容，按优先级和枝区轮换分配标签预算，解决屏幕文字碰撞。 |
| `IllustratedTreeRenderer.tsx` | 绘制插画骨架、装饰叶片、固定屏幕字号标签和交互区域。 |
| `TreeKnowledgePanel.tsx` | 打开聚合内容，搜索并选择原始节点；选择后转入现有正文和属性面板。 |
| `TreeView.tsx` / `Workspace.tsx` | 连接新布局与现有数据；提供持久化的新旧布局菜单。 |
| `useTreeCamera.ts` / `TreeMinimap.tsx` | 按整树边界设置开场视野，缩略图显示骨架，调整窗口或面板后保持视野可用。 |

## 生成方式

树冠使用五个预留区域，整体中部展开，下部较窄，上部收束，左右略不对称。枝条在不同站位分叉，主枝先延伸，再长出二级枝。每个二级子树的曲线和枝梢保持在自己的主枝区域内。有限的重量参数只在区域内改变枝长，不能增加槽位或破坏容量上限。

阶段超过五个时，连续阶段合并为阶段组；较大子树占较大枝区。树上位置不表达年份。缺少阶段字段的子节点沿父链继承阶段。超过容量的领域和技术由最后一个代表集合收纳，通过摘要和知识列表查看。循环父链不会导致递归渲染。

原始节点、关系、Markdown 和存储格式不变。插画模式不把横向关系画成交叉线；相关内容仍由原有关系和正文面板访问。叶片属于装饰，不强迫每个概念成为可见几何。

## 渐进展示

| 状态 | 显示内容 | 标签上限 |
| --- | --- | --- |
| 远景，scale < 0.62 | Subject、Stage / 阶段组、Domain / Major Topic | scale < 0.45 时 12，否则 16 |
| 中景，0.62 ≤ scale < 1.05 | 加入 Topic | 28 |
| 近景，scale ≥ 1.05 | 加入 Technology 枝梢 | 50 |
| 悬停 / 选择 | 全名、节点类型、阶段和已有来源属性；概念在列表及正文中查看 | 不突破当前标签预算 |

文字字号为屏幕像素：学科 18、阶段 14、其他标签 12。标题过长时缩略显示，但保留 `+N` 摘要，全文可在提示和列表中访问。碰撞按屏幕文字边界和间距处理，不能通过缩小字号或让所有标签常驻解决。预算是上限；避碰及视口裁剪可以进一步减少标签。

## 验收证据（2026-10-06）

- 现有知识库的只读快照：117 个节点、12 个阶段映射为 5 根主枝。
- 常用桌面窗口 1040 × 680：开场 12 个标签，默认展示整树。选择知识条目后打开真实工作区的正文面板并关闭聚合列表。
- 1280 × 1000 预览：开场 16 个标签；中景显示领域与主题；近景出现技术枝梢。
- 压力样例 1,465 个节点：可见几何受固定槽位控制；所有原始节点均可从代表集合访问。
- 单元测试涵盖一根主干、5 根主枝、分叉容量、渐细宽度、向上生长、分枝错位、子树区域隔离、确定性、输入顺序和旧坐标无关性、知识可达性、阶段继承、大小分配、循环输入、LOD 和标签碰撞。
- 浏览器测试测量实际 SVG 文本边界，检查聚合列表、工作区正文、视图切换和本机设置保存。预览使用浏览器 API 适配器；它验证前端流程，正式桌面仍使用原有 Tauri API。

截图和浏览器检查记录位于 `artifacts/illustrated-tree-*`。本地预览入口 `frontend/illustrated-tree-preview.html` 不进入生产首页；`frontend/preview/actual-data.json` 仅含这次视觉检查所用的结构快照，不是知识库存储来源。

插画布局阶段前端 35 项测试通过，TypeScript / Vite 生产构建通过。后续交互优化验收见 `ux-interaction-optimization.md`。当前正式版本为 **0.1.0**，最新程序统一为 `target/release/knowledge-tree-desktop.exe`，旧程序备份已清理。使用 `--no-bundle` 构建，未重新生成 NSIS 安装程序。

## 复查

```powershell
pnpm test:ui
pnpm build:ui
pnpm --dir frontend dev
```

浏览器复查脚本为 `scripts/preview-illustrated-tree.cjs` 和 `scripts/check-illustrated-workspace.cjs`。需要 Playwright、Chrome 和本地 Vite。使用运行环境中已有的 Playwright 时设置 `NODE_PATH`；`TREE_PREVIEW_URL` 可指定示例或结构快照入口。

视觉审美仍需人工看图；没有把“像树”的主观判断当作自动测试可以证明的结论。后续可以替换枝区模板，或加入更多插画骨架，而不用修改知识存储。
